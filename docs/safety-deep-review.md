# 深度安全审查配置说明

本文档对应内置版本 `2026.11.24-3`。所有内容都可在后台「安全审查」页面直接修改、停用、删除；
本文件只说明设计意图与推荐配置，不替代后台的可视化编辑。

## 一、处理动作与优先级

一个词库声明自己的默认处理动作（`hit_action`）；一条规则可引用多个词库，命中后按**最严动作**汇总：

| 动作 | 含义 | 对请求的影响 | 日志/响应头 |
|---|---|---|---|
| `block` | 拦截 | 不调用上游，直接返回规则配置的默认回复 | `X-Safety-Review: blocked_input / blocked_output` |
| `sanitize` | 脱敏 | 命中片段替换为 `***` 后继续；输入在发往上游前改写，输出在返回客户端前改写 | `sanitized_input / sanitized_output` |
| `review` | 复核 | 原样放行，只在审查记录里登记待人工复核 | `review_input / review_output` |

优先级：`block > sanitize > review`。例如同一段文本既命中涉毒（block）又命中隐私（sanitize），按 block 处理。

> 流式输出命中 `sanitize` 时，已发出的增量无法回收，系统会丢弃原缓冲、用脱敏后的整段文本重发一个合法 SSE 流，
> 客户端收到的是一条完整的脱敏回复，而不是逐字的原始内容。

## 二、风险分级

`risk_level` 仅用于排序、统计和后台展示，不直接决定动作；动作由 `hit_action` 决定。

| 等级 | 建议场景 |
|---|---|
| `low` | 提示性标记，通常配 `review` |
| `medium` | 隐私类，通常配 `sanitize` |
| `high` | 涉毒/涉黄/暴力/犯罪等明确违规，配 `block` |
| `critical` | 涉政、涉未成年色情等零容忍类别，必须 `block` |

## 三、类别配置表

| 词库（builtin_key） | 类别 | 风险等级 | 动作 | 触发条件（匹配模式） | 典型例外（不拦截） |
|---|---|---|---|---|---|
| `builtin:deep_political` | 涉政 | critical | block | 「违规行为 + 对象」正则组合，如 `煽动…分裂国家`、`造谣…领导人…病情`、`境外势力…资助…颠覆` | 正面政治表述、政务报道、党史学习、宪法条文 |
| `builtin:deep_drug` | 涉毒 | high | block | 高危毒品名逐词匹配；易歧义词（大麻、溜冰、飞叶子）只做「行为 + 词」组合 | 「溜冰是冬季运动」「大麻烦」「反毒品宣传教育」 |
| `builtin:deep_porn` | 涉黄（成人） | high | block | 「限定词 + 载体/交易」，如 `色情…网站/视频`、`特殊服务…多少钱`、`援交/包夜` | 「成人教育」「性教育课程」「生理卫生」 |
| `builtin:deep_porn_minor` | 涉未成年色情 | critical | block | `儿童/幼女/未成年…色情/裸照/性侵`、`萝莉/正太…裸/色情` | 无。零容忍，不应改为 sanitize/review |
| `builtin:deep_violence` | 暴力与自伤 | high | block | `制作…炸弹/枪支`、`虐杀/肢解`、`自杀…方法/无痛`、`绑架…流程` | 「消防安全教育」「自杀预防与心理援助」 |
| `builtin:deep_crime` | 犯罪手法 | high | block | `诈骗…话术/模板`、`洗钱…平台/接单`、`伪造…证件`、`贩卖…个人信息` | 「反洗钱合规宣传」「反诈科普」「防范非法集资」 |
| `builtin:deep_privacy` | 隐私 | medium | sanitize | 身份证/银行卡/手机号/邮箱/IP 正则，以及「字段名 + 值」组合 | 普通产品说明、无个人信息的业务文本 |

对应的三条内置规则：

| 规则（builtin_key） | 引用词库 | 方向 | 拆字识别 | 用途 |
|---|---|---|---|---|
| `builtin:deep-policy` | 全部 7 个深度库 | 输入 + 输出 | 开 | 一站式深度审查：高危拦截、隐私脱敏 |
| `builtin:vice-policy` | 涉毒 + 涉黄 + 涉未成年 | 输入 + 输出 | 开 | 强合规场景（对外部用户开放的 Key） |
| `builtin:privacy-sanitize` | 隐私 | 输入 + 输出 | 关 | 只脱敏不阻断，适合内部数据分析 |

以上三条**默认都不启用**，需在后台把规则绑定到指定 Key，或显式设为默认规则。

## 四、匹配能力与变体覆盖

| 能力 | 实现方式 | 适用范围 |
|---|---|---|
| 同义变体 | 词库中直接枚举（如 `海洛因`/`冰毒`/`甲基苯丙胺`，`诈骗`/`骗术`/`话术`） | 全部 |
| 拆字绕过 | 规则级开关 `aggressive_normalize`：为词条生成「字间允许 0-3 个轻分隔符」的正则，并对正则类词条额外匹配「去分隔符紧凑文本」 | 开启拆字的规则 |
| 谐音/暗语 | 不做拼音算法（误伤不可控），改为在词库中枚举常见黑话（溜冰、打K、飞叶子）并强制「行为 + 词」组合 | 涉毒等 |
| 组合表达 | 用 `.{0,N}` 连接「行为动作」与「对象」，如 `教我…洗钱`、`制作…炸弹` | 全部 |
| 上下文语义 | 通过「限定词 + 载体」「否定前缀排除」等组合把裸词升级为意图判断；**不引入模型语义判定**（避免把可用性绑到第三方） | 全部 |

拆字识别的分隔符刻意只包含空格、点、短横、下划线、间隔号、零宽字符，**不含句号/逗号/顿号**，
避免「中毒。品质」被误判成「毒品」。单次最多允许 3 个分隔符，控制误伤。

## 五、误伤控制建议

1. **默认不接管**：深度规则一律 `is_default=false`，先绑定到 1-2 个测试 Key 观察审查记录，再逐步扩面。
2. **先用复核再收紧**：对不确定的类别，可先复制词库把 `hit_action` 改为 `review`，观察一周命中样本后再切 `block`。
3. **隐私类优先脱敏**：`sanitize` 保留业务语义，比直接拦截更适合数据分析、客服质检等场景。
4. **按业务排除**：招标/评标、政务、医疗、教育等文本会频繁出现「国家安全」「未成年人」「自杀预防」等正常词，
   建议为这类 Key 单独建规则，只引用必需的高危库，不要直接绑定 `deep-policy`。
5. **阈值兜底**：对短词（2 字以内）居多的自建词库，可把规则 `threshold` 设为 2，要求同时命中两个词才处置。
6. **零容忍不可降级**：`builtin:deep_porn_minor` 必须保持 `block`，不要改成 `sanitize` 或 `review`。
